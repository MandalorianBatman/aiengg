## Core Definitions

### Large Language Model (LLM)
> **Lecture's take:** A neural network trained to predict the next token of an input sequence. The output is appended to the input, and the next token is predicted again. This autoregressive loop produces the full response. Gaurav deliberately avoids the word "world" — the only objective is next-token prediction.

**Canonical definition.** An LLM is a transformer-stack that has been trained on large corpora with the single objective of next-token prediction. Given a sequence of tokens, the model outputs a probability distribution over its vocabulary for the next token, samples (or argmaxes) one, appends it to the context, and repeats — this autoregressive loop is what generates text.

**Key insight.** "Next-token prediction" is the *only* training objective, yet it implicitly induces grammar, world knowledge, and reasoning ability when the model and corpus are large enough. The model is not "trying to understand the world" — it is minimising cross-entropy on text, and understanding emerges as a side effect.

- [Andrej Karpathy — "Let's build GPT: from scratch, in code, spelled out"](https://www.youtube.com/watch?v=kCc8FmEb1nY) — *a 4-hour walkthrough that builds a GPT in PyTorch, line by line.*

### Token
> **Lecture's take:** A unit of text consumed by the model. Generated by an algorithm like **Byte Pair Encoding (BPE)**. Often sub-word — "coronation" may split into "coro" + "nation". Surprising at the surface, but optimised for LLM consumption.

**Canonical definition.** A token is an atomic subword unit drawn from a fixed vocabulary. Modern LLMs do not consume raw characters or whole words — they consume tokens produced by a deterministic tokenizer (most commonly BPE or a variant like WordPiece or Unigram). The same English word can map to 1 token in some contexts and several in others.

**Key insight.** The token vocabulary is part of the model, not separate from it. The model's embedding matrix has one row per vocabulary token, and the output linear layer has one column per vocabulary token. Vocabulary size therefore directly controls the size of two of the model's largest weight matrices.

- [HuggingFace LLM Course — Chapter 2, §4: Tokenizers](https://huggingface.co/learn/llm-course/chapter2/4) — *practical walkthrough of BPE, WordPiece, and Unigram tokenizers.*

### Byte Pair Encoding (BPE)
> **Lecture's take:** A greedy compression-style algorithm. Start with a base alphabet (characters or bytes), repeatedly merge the most frequent adjacent pair, and stop when the vocabulary hits a target size. The lecture does not run through the algorithm in detail — it is named and used as the canonical example of a tokenizer.

**Canonical definition.** BPE builds a vocabulary bottom-up: start with a base alphabet (e.g., 256 UTF-8 bytes), then iteratively merge the most frequent adjacent pair into a new symbol until the vocabulary reaches a target size. The result is a vocabulary of frequent subwords — common words stay whole, rare words split into pieces.

**Key insight.** BPE was invented for data compression (Gage, 1994) and repurposed for NLP by Sennrich et al. (2016). For LLMs, the practical consequence is that *no token is ever OOV (out-of-vocabulary)*: any string can be decomposed into the base alphabet, so the model always has something to embed.

**📚 Further reading**
- [Sennrich et al., 2016 (arXiv:1508.07909)](https://arxiv.org/abs/1508.07909) — *the canonical BPE-for-NLP paper.*
- [rsennrich/subword-nmt — reference implementation](https://github.com/rsennrich/subword-nmt) — *the implementation that became the de-facto standard.*

### Vector (Embedding)
> **Lecture's take:** A coordinate in a multi-dimensional space assigned to each token. Common dimensions: **768, 8192**. Each dimension is conceptually a "feature" the model has learned (e.g., "how south is this city from Delhi"). In reality, the model is just predicting the next token — we don't know what each dimension truly represents.

**Canonical definition.** An embedding is a learned mapping from a discrete token (or word, or concept) into a dense, real-valued vector. Semantically similar tokens end up close together in the embedding space, and arithmetic over embeddings can capture analogies ("king − man + woman ≈ queen").

**Key insight.** The individual dimensions of an embedding are *not* human-readable. They are arbitrary rotations of the underlying feature axes the model uses internally. Tools like PCA or probing classifiers can recover interpretable directions, but the raw vector is a coordinate in a space the model chose, not us.

**📚 Further reading**
- [Mikolov et al., 2013 — "Efficient Estimation of Word Representations in Vector Space"](https://arxiv.org/abs/1301.3781) — *Word2Vec — the paper that popularised the modern notion of word embeddings.*
- [3Blue1Brown — "But what is a GPT?"](https://www.3blue1brown.com/lessons/gpt/) — *visual intuition for how embedding space is built up by attention.*
- [Jay Alammar — "The Illustrated Word2vec"](https://jalammar.github.io/illustrated-word2vec/) — *visual walkthrough of how embeddings encode meaning.*

## The Transformer Architecture

The lecture walks through the transformer block by block. The shape annotations are kept as Gaurav wrote them; canonical references are added below.

| Step | Block | Input Shape | Output Shape | Notes |
|------|-------|-------------|--------------|-------|
| 1 | Tokenize | text | N tokens | BPE / WordPiece / Unigram |
| 2 | Embedding | N tokens | N × D | D = 768 (GPT-2) or 8192 (current large models) typical |
| 3 | Positional encoding | N × D | N × D | Adds position info (sinusoidal in original; RoPE in modern LLMs) |
| 4 | Layer Norm | N × D | N × D | Root-mean-square normalize |
| 5 | QKV linear | N × D | 3 × (N × D) | Query, Key, Value matrices |
| 6 | Attention (Q·K^T) | 3 × (N × D) | N × N | Similarity matrix (masked: lower-triangular) |
| 7 | Softmax × V | N × N, N × D | N × D | Contextualized vectors |
| 8 | Layer Norm | N × D | N × D | |
| 9 | Feed-Forward Network | N × D | N × D | Same shape, transformed values |
| 10 | Layer Norm | N × D | N × D | |
| 11 | Linear (unembedding) | N × D | N × \|vocab\| | Probability distribution |

### Transformer
> **Lecture's take:** The internal architecture of an LLM. The lecture walks through it block by block rather than defining it up front.

**Canonical definition.** The transformer (Vaswani et al., 2017) is a neural-network architecture built around the **scaled dot-product attention** mechanism. A transformer block is: attention → add & norm → feed-forward → add & norm. Modern LLMs stack dozens to hundreds of these blocks; the input embedding layer and the output unembedding layer bracket the stack.

**Key insight.** Pre-transformer sequence models (RNN, LSTM) processed tokens one at a time, which prevented parallelisation and made long-range dependencies hard to learn. The transformer's attention lets every token look at every other token in O(1) sequential steps — the cost is the N×N similarity matrix, which is what constrains the context window.

**📚 Further reading**
- [Vaswani et al., 2017 — "Attention Is All You Need"](https://arxiv.org/abs/1706.03762) — *the paper. Read §3 (Model Architecture) end-to-end.*
- [Jay Alammar — "The Illustrated Transformer"](https://jalammar.github.io/illustrated-transformer/) — *the most-cited visual walkthrough of the paper.*
- [3Blue1Brown — "Attention in transformers, step-by-step"](https://www.3blue1brown.com/lessons/attention/) — *visual intuition for the Q·K^T step.*

### Positional encoding
> **Lecture's take:** The transformer needs to know the position of each token in the sequence. A positional encoding is added to each token's embedding so that "the dog bit the man" and "the man bit the dog" produce different vectors.

**Canonical definition.** Positional encoding injects order information into a permutation-equivariant architecture. The original transformer uses fixed sinusoidal encodings of the form `PE(pos, 2i) = sin(pos / 10000^(2i/D))`. Most modern LLMs use Rotary Position Embeddings (RoPE), which rotates each query/key vector by an angle proportional to its position.

**Key insight.** Attention itself is symmetric — it treats the input as a set, not a sequence. Without positional encoding, "cat eats fish" and "fish eats cat" would be indistinguishable. RoPE is dominant today because it generalises better to context lengths longer than those seen at training time ("length extrapolation").

**📚 Further reading**
- [Vaswani et al., 2017 — §3.5](https://arxiv.org/abs/1706.03762) — *original sinusoidal positional encoding.*
- [Su et al., 2021 — "RoFormer: Enhanced Transformer with Rotary Position Embedding"](https://arxiv.org/abs/2104.09864) — *the RoPE paper.*
- [Lilian Weng — "Attention? Attention!"](https://lilianweng.github.io/posts/2018-06-24-attention/) — *§"Positional Encoding" walks through sinusoidal and RoPE side-by-side.*

### Layer normalization (and RMSNorm)
> **Lecture's take:** The lecture mentions layer norm as the "root-mean-square normalize" step that runs alongside attention and the FFN. The deeper mechanics are not explored.

**Canonical definition.** LayerNorm (Ba, Kiros & Hinton, 2016) normalises activations across the feature dimension for each token independently: subtract the mean, divide by the standard deviation, apply learned scale and bias. RMSNorm (Zhang & Sennrich, 2019) is a faster variant that drops the mean-centering and re-normalisation step.

**Key insight.** LayerNorm is preferred over BatchNorm for transformers because it works on a single example (no batch dependence) and gives the same result at train and inference time. RMSNorm is used in Llama, Mistral, and most modern open models because it's roughly 30–50% cheaper to compute with negligible quality loss.

**📚 Further reading**
- [Ba, Kiros & Hinton, 2016 — "Layer Normalization"](https://arxiv.org/abs/1607.06450) — *the original LayerNorm paper.*
- [Zhang & Sennrich, 2019 — "Root Mean Square Layer Normalization"](https://arxiv.org/abs/1910.07467) — *the RMSNorm paper.*
- [Lilian Weng — "Attention? Attention!"](https://lilianweng.github.io/posts/2018-06-24-attention/) — *§"Layer Normalization" with worked example.*

## Key Concepts Explained

### Attention
> **Lecture's take:** Each token looks at every other token, computes similarity scores, and gets **pushed in the right direction**. Ambiguous vectors become **contextualized vectors** — they now know the context they're in.
> *"Before this, plant just knew that I'm plant. But it didn't know whether I'm the organism or the factory because it had not looked at the nearby words."*

**Canonical definition.** Attention (scaled dot-product) computes, for each query vector, a weighted sum of all value vectors, where the weights are a softmax of the dot-product similarity between the query and each key. In one step, every position can pull information from every other position.

**Key insight.** Attention is the only operation in the transformer that lets information move *between* positions. The FFN operates per-position; everything else is just per-position transformations and normalisation. This is why attention is the architectural bottleneck: the N×N similarity matrix is what makes the context window a hard ceiling.

**📚 Further reading**
- [Vaswani et al., 2017 — §3.2.1](https://arxiv.org/abs/1706.03762) — *the canonical scaled dot-product attention formula.*
- [Jay Alammar — "The Illustrated Transformer"](https://jalammar.github.io/illustrated-transformer/) — *visual walkthrough of Q·K^T → softmax → weighted sum of V.*
- [3Blue1Brown — "Attention in transformers, step-by-step"](https://www.3blue1brown.com/lessons/attention/) — *visual intuition for the weighted-average-of-values step.*

### Q, K, V (Query, Key, Value)
> **Lecture's take:** Three vectors per token, computed by multiplying the input vector with three matrices. The attention formula: `sim = Q · K^T; output = softmax(sim) · V`. The lecture defers the deeper "why three matrices" question to a math deep-dive.

**Canonical definition.** Three learnable projection matrices (`W_Q`, `W_K`, `W_V`) are applied to each input vector to produce three vectors per token. During attention, the **query** asks "what am I looking for?", the **key** advertises "what do I contain?", and the **value** carries the actual information to be aggregated.

**Key insight.** Conceptually, Q, K, and V could all come from the same vector — they are three different learned "views" of the input. The reason three matrices work better than one is that they let the model decouple *what a token is asking for* from *what it advertises* from *what it actually contributes* to the output. Three separate projections give the model enough capacity to learn distinct roles.

**📚 Further reading**
- [Vaswani et al., 2017 — §3.2.1](https://arxiv.org/abs/1706.03762) — *Q/K/V definitions in the original paper.*
- [Jay Alammar — "The Illustrated Transformer"](https://jalammar.github.io/illustrated-transformer/) — *clearest visual explanation of the Q/K/V role split.*
- [Lilian Weng — "Attention? Attention!"](https://lilianweng.github.io/posts/2018-06-24-attention/) — *"Scaled Dot-Product Attention" section.*

### Multi-head attention
> **Lecture's take:** Multiple attention heads run in parallel, each learning different relationships (e.g., one head for grammar, another for topical relevance).

**Canonical definition.** Instead of one Q/K/V projection, multi-head attention learns `h` independent sets of Q/K/V projections. Each head computes its own attention pattern; the outputs are concatenated and projected back to the model dimension. With D = 8192 and `h = 128`, each head works in a 64-D subspace.

**Key insight.** Different heads reliably learn different functions: one head tracks the previous token, one attends to syntactic dependents, some become "induction heads" that copy patterns seen earlier in the context. This was a striking empirical finding from mechanistic interpretability work and is a major reason LLMs can do in-context learning.

**📚 Further reading**
- [Vaswani et al., 2017 — §3.2.2](https://arxiv.org/abs/1706.03762) — *Multi-Head Attention.*
- [Elhage et al., 2021 — "A Mathematical Framework for Transformer Circuits"](https://transformer-circuits.pub/2021/framework/index.html) — *"Induction heads" — the most influential multi-head behaviour discovered.*

### Masked attention (causal masking)
> **Lecture's take:** The upper triangle of the similarity matrix is masked — tokens can't look ahead. **Why?** Because masking turns one sentence into **N training pairs** (one per token), not just one. With N tokens, you get N predictions and N places to compute loss.

**Canonical definition.** Causal masking zeroes out the upper triangle of the N×N similarity matrix before softmax, so position `i` can only attend to positions `≤ i`. This is what makes the transformer autoregressive — it cannot cheat by looking at the next token it is supposed to predict.

**Key insight.** Masked attention is what makes language modelling work as a *self-supervised* training task. Without masking, the model could trivially copy the next token from its context and cross-entropy would be zero everywhere. Masking converts "predict the next token" into N supervised prediction problems per sentence — that's why one page of text gives you thousands of training gradients.

**📚 Further reading**
- [Andrej Karpathy — "Let's build GPT"](https://www.youtube.com/watch?v=kCc8FmEb1nY) — *the clearest walkthrough of causal masking and why it matters.*
- [Vaswani et al., 2017 — §3.2.3](https://arxiv.org/abs/1706.03762) — *encoder/decoder attention masking in the original paper.*

### Feed-forward network (FFN)
> **Lecture's take:** A per-token block that maps 8192-D → 8192-D but with transformed values. **Analogy:** Just like deriving "area" from "length × breadth" or "ratio" from "length / breadth", the FFN builds new features from old ones.
> *"These don't have new information. They are just a transformation, a mapping of our existing features into more useful features."*

**Canonical definition.** The position-wise FFN is a two-layer MLP applied independently to each token's vector: `FFN(x) = W₂ · σ(W₁ · x + b₁) + b₂`, typically with the inner dimension 4× the model dimension (e.g., 8192 → 32768 → 8192). The nonlinearity `σ` is ReLU in the original paper; modern LLMs use SwiGLU or GeLU.

**Key insight.** Attention is the only place where information moves *between* tokens; the FFN is where each token's vector gets transformed in place. Recent mechanistic-interpretability work shows the "up-projection" matrix `W₁` is where the model stores its factual knowledge — it's literally a key-value lookup from token features to fact rows.

**📚 Further reading**
- [Vaswani et al., 2017 — §3.3](https://arxiv.org/abs/1706.03762) — *the FFN definition.*
- [Sebastian Raschka — "Build a Large Language Model (From Scratch)"](https://www.manning.com/books/build-a-large-language-model-from-scratch) — *builds an FFN from scratch with worked code.*
- [Elhage et al., 2022 — "Softmax Linear Units"](https://transformer-circuits.pub/2022/solu/index.html) — *why SwiGLU replaced ReLU in modern FFNs.*

### Linear layer / Unembedding (LM head)
> **Lecture's take:** The final linear layer maps the contextualized N × D vectors to N × \|vocab\| probabilities. The argmax (or sample) over the row at the last position is the predicted next token.

**Canonical definition.** The output projection (often called the "LM head" or "unembedding matrix") is a linear layer `W_U ∈ R^{D × |V|}` that maps each contextualized vector to a logit over the entire vocabulary. A softmax over those logits gives the next-token probability distribution.

**Key insight.** The unembedding matrix is one of the two largest weight matrices in the model (the other being the embedding matrix). Weight tying — sharing the unembedding matrix with the embedding matrix — is a common optimization that halves the parameter count of these layers with minimal quality loss.

**📚 Further reading**
- [Jay Alammar — "Illustrated GPT-2"](https://jalammar.github.io/illustrated-gpt2/) — *visual walkthrough of the unembedding step.*
- [Sebastian Raschka — "Build a Large Language Model (From Scratch)"](https://www.manning.com/books/build-a-large-language-model-from-scratch) — *chapter on the LM head, including weight tying.*

### Vocabulary
> **Lecture's take:** The set of tokens the model knows. Output distribution has one probability per vocabulary token. Smaller vocab = cheaper output layer.

**Canonical definition.** The vocabulary is the fixed, finite set of tokens the model can read or write. Vocabulary sizes range from ~32k (GPT-2) to ~256k (Llama 3) to ~258k (DeepSeek-V3). Every vocabulary token has exactly one row in the embedding matrix and exactly one column in the unembedding matrix.

**Key insight.** Vocabulary size is a trade-off: a larger vocabulary makes text shorter (fewer tokens per word, faster inference for the user) but makes the embedding and unembedding matrices bigger and slows down softmax over the logits at every step. Modern choices balance this against byte-level fallback (which would make any string exactly 1 byte per character but blow up sequence length).

**📚 Further reading**
- [HuggingFace LLM Course — Chapter 2, §4: Tokenizers](https://huggingface.co/learn/llm-course/chapter2/4) — *vocabulary construction in practice.*
- [Andrej Karpathy — "Let's build the GPT Tokenizer"](https://www.youtube.com/watch?v=zduSFxRajkE) — *tradeoffs in vocabulary design.*

## Side Concepts

### N-grams vs LLMs
> **Lecture's take:** Both do next-token prediction. **N-grams** use simple frequency counts; **LLMs** use massive learned transformations. Google has been doing vector-based next-token prediction since 2012.

**Canonical definition.** A classical n-gram language model estimates `P(token_i | token_{i-1}, …, token_{i-n+1})` by counting how often that exact sequence appeared in a corpus. An LLM does the same prediction but with a learned, deep transformation of the entire prior context.

**Key insight.** The formulation is identical — conditional next-token probability — which is why the lecture can teach them in the same breath. What changes is the *capacity* of the conditional: an n-gram memorises a lookup table; an LLM generalises across compositional structure. The shift from "memorise" to "compose" is the entire reason modern NLP works.

**📚 Further reading**
- [Jurafsky & Martin — "Speech and Language Processing" Ch. 3 (online draft)](https://web.stanford.edu/~jurafsky/slp3/) — *the canonical n-gram chapter.*
- [3Blue1Brown — "But what is a GPT?"](https://www.3blue1brown.com/lessons/gpt/) — *the contrast n-gram ↔ transformer is the central pedagogical move.*

### Context window
> **Lecture's take:** The number of tokens the model can attend to. **1M context ≠ 1M tokens of info** — every token gets context from the remaining 1M tokens, and this happens 1M times. Dramatic compute cost.

**Canonical definition.** The context window is the maximum number of tokens the model can attend to in a single forward pass. It is bounded by the size of the N×N attention matrix, which scales quadratically in the number of tokens. Modern long-context models use techniques like FlashAttention, Ring Attention, and KV-cache compression to extend the effective window.

**Key insight.** "Context window" is often misunderstood as a measure of *memory*. It is not — the model has no persistent memory outside the current context. A 1M-token context also costs 1M² entries in the attention matrix per layer, which is why long-context inference is several times slower than short-context inference.

**📚 Further reading**
- [Vaswani et al., 2017 — §3.2.1](https://arxiv.org/abs/1706.03762) — *the quadratic-cost motivation for the original transformer's 512-token window.*
- [Jay Alammar — "Illustrated GPT-2"](https://jalammar.github.io/illustrated-gpt2/) — *clear visual on why context matters.*
- [Dao et al., 2022 — "FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness"](https://arxiv.org/abs/2205.14135) — *the most important practical paper for long-context LLMs.*

### KV cache
> **Lecture's take:** Memoization of Key and Value vectors for previously-seen tokens. Avoids recomputing the entire N × N similarity matrix on every new token. **Memory-expensive but worth it.**

**Canonical definition.** During autoregressive generation, the keys and values for every previously processed token are stored in a per-layer, per-head cache. When a new token arrives, only its Q/K/V is computed; the new Q attends to the cached K and V of all prior tokens, and the new K/V are appended to the cache.

**Key insight.** Without the KV cache, generating N tokens would cost O(N²) total attention work (each new token would re-attend to all prior tokens from scratch). With the KV cache, each new token costs O(N) — a massive speedup. The trade-off is memory: KV cache size grows linearly with `batch × seq_len × n_layers × n_heads × head_dim`, which is what drives most of the cost of long-context serving.

**📚 Further reading**
- [HuggingFace Transformers — KV caching documentation](https://huggingface.co/docs/transformers/en/kv_cache) — *practical guide to enabling and tuning KV caching.*
- [HuggingFace Cookbook — "Speed up inference with the KV cache"](https://huggingface.co/learn/cookbook/en/llm_inference_speed) — *concrete code examples and benchmarks.*

### Input vs Output tokens
> **Lecture's take:** **Input tokens** are the context the model receives (docs, search results, chat history); **output tokens** are what the model generates. In typical apps, input tokens > output tokens.

**Canonical definition.** Input and output tokens are billed separately by every commercial API because they incur different costs. Input tokens cost roughly the same as one forward pass; output tokens cost N forward passes (one per generated token, because of autoregression and KV-cache updates).

**Key insight.** For chat or retrieval-augmented apps, the input side is dominated by retrieved documents, chat history, and tool outputs — not the user's question. This is why long-context and efficient retrieval matter more than raw tokens-per-second: a 10× larger context window lets the model see 10× more retrieved evidence, which often matters more than 10× faster generation.

**📚 Further reading**
- [HuggingFace Cookbook — "Speed up inference with the KV cache"](https://huggingface.co/learn/cookbook/en/llm_inference_speed) — *concrete cost breakdown of input vs. output tokens.*

## Key Takeaways

1. **LLM = transformer-stack** predicting next token autoregressively
2. **Tokens** are sub-word units (BPE) mapped to vectors in high-D space
3. **Attention** turns ambiguous vectors into contextualized vectors via Q/K/V similarity
4. **Masked attention** gives N training signals per N-token sentence
5. **Feed-forward** layers transform features into more useful features (same shape in/out)
6. **Linear layer** at the end → probability distribution over vocabulary
7. **KV cache** and **vocabulary size** are critical for performance and cost
